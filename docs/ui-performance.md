# UI 性能维护

2.2.1 的目标是改善页面切换与字幕绘制，保持页面、控件、输入方式、布局和功能。源码基线为 `3ed25b9e`；正式源码身份以 `v2.2.1` 标签和包内 `BUILD_INFO.json` 为准，本机安装身份另由 Apps 索引和交付回执记录。

## 已验证的修改

- Button/Entry/Combobox 的背景在全部状态下固定为 `surface`，Notebook/Tab 为 `canvas`。对应圆角图片在创建时预先合成到该背景，降低 Windows Tk 反复进行透明混合的成本。箭头、复选框、滑块、轨道、滚动条和进度条保留透明合成；它们可能与其他元素重叠。
- 首次映射控件时安装输入 bindtag；再次切页时在 Tcl 内跳过已安装控件，不递归重复遍历子树。弹层映射处理只绑定 TCombobox。动态创建、键盘/鼠标模式、取消和单次提交仍沿原入口。
- 主线程每批消息保留 100 条上限，并增加 6ms 协作预算；超时后保留 FIFO 顺序，1ms 后继续。一个回调与显示提交仍可能超过预算，此数值不代表硬实时保证。
- 字幕背景和圆角蒙版每实例只缓存当前一组，键覆盖尺寸、圆角、背景色和实际 alpha。合成不修改缓存；额外保留约 `5 × 宽 × 高` 字节，770×983 时约 3.61MiB。

## 复测入口

使用项目既有 Windows Python，输出指定到当前对话的 E 盘工作区。源码基准使用隔离设置、不采音，正常结束时检查正式配置未变、回调错误为空、运行前后源码一致。

```text
python -B tools/benchmark_ui.py --output E:/AI/<对话目录>/evidence/ui --samples 15
python -B tools/benchmark_rendering.py --baseline-source E:/AI/<对话目录>/evidence/baseline-overlay.py --output E:/AI/<对话目录>/evidence/rendering --samples 40
python -B -m unittest discover -s tests
```

切页基准覆盖五页和深浅两主题，计时包含 Tk 选择页面与待处理工作；它不测物理点击到屏幕发光的时延。字幕基准在相同 64 段输入下交替执行原版和修改版，比较静态、滚动、末段变化、尺寸/颜色/透明度/圆角变化的完整 RGBA 帧。

本轮 Windows 样本中，深/浅主题切页中位数为 80.92/75.97ms → 52.14/49.70ms；p95 为 301.09/318.35ms → 182.30/82.31ms。切页长尾有环境波动，不以一次最快值作保证。常规字幕合成中位数降低约 21%，末段更新约 10.5%；持续改变尺寸等失效路径约持平。344 帧完整 RGBA 一致。主题真实截图覆盖普通、悬停、按下、焦点、禁用、错误及组合状态；内容区仅有不超过 2/255 的抗锯齿舍入差异。

## 本次交付缺口的修正

此前组件走查覆盖外观与操作，没有保留切页耗时基线。已加入上述可重复基准，后续修改 Map 绑定、主题图片或显示调度时按受影响场景复测；不把静态看图通过当成流畅性验证。实测原生绘制成本显著高于 Python 回调，重复控件遍历只解释部分成本，不能据此扩大归因到识别 worker。音频、字幕历史、待译段与译文缓存已有容量上限，本轮保持其架构。
