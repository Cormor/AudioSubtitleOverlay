# 译文随语音更新

打开“显示译文”，选好目标语言和翻译方式，点击“开始字幕”。原文草稿出现后，声幕就会翻译当前片段；讲话继续时，译文在同一段中更新，原文定稿后再对齐最终结果。

## 看懂当前状态

- 原文已出现、翻译尚未返回时，译文位置显示“翻译中”。
- 译文已经对应当前原文草稿时，显示“草稿”。
- 原文继续增长、译文尚未覆盖新增内容时，保留适用的译文并标注“更新中”，后续模型结果继续替换它。
- 当前段原文和最终译文对应后，移除更新提示。

译文沿用个人设置中的颜色、字号和透明度。“更新中”表示内容还会修订，不会把已返回的译文当占位文字淡化。

## 设置与使用

在“实时字幕”页选择目标语言和翻译方式；只看原文时，关闭“显示译文”。源语言与目标语言相同时不调用翻译。运行中调整译文开关、目标语言或翻译方式，会按新选择刷新译文，识别继续使用当前音源。

- **仅使用本地翻译**：由本机Argos模型处理。第一次使用缺少的语言对时，仍需要准备对应模型。
- **仅使用免费在线MyMemory**：把当前片段文字交给在线服务；片段修订时可能再次提交该片段。
- **本地优先，失败转在线**：本地模型可用时先使用本地；模型缺失或本地翻译失败时改用MyMemory。

模型每次根据当前片段生成结果。片段增长、识别纠错和上下文变化都可能改变后续译文，句子结束前适合跟读，不宜把草稿当作定稿引用。

原文只是继续增长时，较早完成、仍适用的译文可以先显示；原文改写后，不适用的旧译文会清除，等待新结果。识别草稿末尾的临时句号或问号可以随正文增长移动，已完成的译文仍能及时显示。英文词内改写，例如I can变为I cannot或I can’t，会使原词对应的旧译文失效。

## 影响等待的因素

短草稿会合并后再提交，当前段定稿时会立即安排最终翻译。识别更新较快而翻译较慢时，同一段只等待最新快照，避免逐条重放过时草稿；已经完成且仍适用的译文先显示。实际等待取决于音频、识别模型、翻译模型和网络，不能由刷新间隔直接换算。

翻译暂时失败时，原文继续更新；检查当前语言、模型或在线连接。切换翻译方式、目标语言或停止后，旧任务的结果不会挂到新的字幕上。

## 本地验证与维护

维护者使用固定WAV回放和安装包诊断，核对同一段在定稿前实际显示多版模型译文、定稿后的精确对应，以及切换设置、停止和故障恢复。翻译中占位不计作译文输出。

工程接口、队列与诊断字段见[维护说明](refactor-2.0.md)。本机运行版本、安装位置与本轮验证记录以Apps索引和对应安装回执为准。
